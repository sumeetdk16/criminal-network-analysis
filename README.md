# AI-Powered Criminal Network Analysis System

**Smart India Hackathon 2026 — Problem Statement 26189**

An investigator decision-support system that ingests fragmented, multi-source
crime data, resolves scattered records into single identities, builds a
relationship graph, ranks influence, detects suspicious patterns, and — for
every single claim it makes — shows the source record behind it.

> All data in this repository is **synthetic**. Every person, phone number,
> account, vehicle, FIR and transaction is fictional and generated by
> `data/generator.py`. No real case material is used anywhere.

---

## Run it

Requires Python 3.10+. No database, no npm, no model downloads.

```bash
python3 -m venv venv && source venv/bin/activate   # or activate your existing venv
cd backend
pip install -r requirements.txt   # includes python-multipart, required for /api/case/upload
python3 ../data/generator.py     # generate the synthetic source data
python3 ../data/make_scans.py    # render the paper-only FIRs (optional)
python3 run.py                   # → http://127.0.0.1:8000
```

Optional extras, each with a stated fallback when absent — the **System** view
in the app reports exactly which are active on your machine:

```bash
# OCR of scanned FIRs, including Devanagari pages
brew install tesseract tesseract-lang        # macOS
sudo apt install tesseract-ocr tesseract-ocr-hin   # Debian/Ubuntu

# encrypt the audit log at rest (AES-256-GCM)
export CNAS_AUDIT_KEY=$(python3 -c "import base64,os;print(base64.b64encode(os.urandom(32)).decode())")

# LLM-written summaries instead of templates (guard-railed, see below)
export CNAS_LLM_ENDPOINT=https://api.openai.com/v1/chat/completions
export CNAS_LLM_KEY=sk-...

# write the graph to a live Neo4j instead of exporting Cypher
pip install neo4j && export NEO4J_URI=bolt://localhost:7687 NEO4J_PASSWORD=...
```

Check everything still works before you present:

```bash
python3 scripts/verify.py        # 63 assertions, including reproducibility
python3 scripts/export_graph.py  # → exports/graph.cypher
```

Open <http://127.0.0.1:8000>. The whole interface is served by the API.

The pipeline runs in-process at startup (about a second). Switch roles with the
selector at the top right to see access control behave differently.

## What it does

**1. Ingests eight fragmented sources.** FIR narratives in English *and*
Devanagari, scanned paper FIRs read by OCR, Call Detail Records, financial
transactions, criminal history records, surveillance reports, social-media
intelligence, and read-only feeds from CCTNS and ICJS.

**2. Extracts entities from unstructured text, in either script.** People,
phone numbers, vehicle registrations, locations, organisations, money and
dates, each with its character span and a confidence, so any node can be traced
to the exact words that produced it. The default extractor is rule + gazetteer
based so it runs offline; a transformer NER model (spaCy / IndicNER) drops into
the same interface when available.

**3. Resolves identities across sources and across scripts.** "Rajesh Kumar",
"R. Kumar" and "Rajesh Kr." become one subject — and so does "विक्रम सेठी" and
"Vikram Sethi", via syllable-aware transliteration and a consonant-skeleton
phonetic key that absorbs Hindi schwa deletion (`imaraana` → `imrn` ← `imran`).
Merges are driven by shared identifiers first, then order-insensitive name
matching that tolerates initials and added middle names — and every merge is
recorded with its reason and score.

**4. Builds a provenance-carrying graph.** Every edge stores its type, weight,
confidence, time window, and the list of source records that produced it.

**5. Ranks influence transparently, with Shapley attribution.** A weighted sum
of betweenness, PageRank, degree, eigenvector centrality, prior record and
cross-group bridging. Because the model is additive, the Shapley value of each
component has a closed form and is computed *exactly* rather than sampled — the
six attributions sum precisely to the gap between a subject's score and the
network average, and the app draws them as a bar chart.

**6. Detects nine kinds of suspicious pattern.** Communication bursts, burner
handsets, circular fund flows, structuring below the reporting threshold,
insulated command profiles, clean-skin bridges, cross-community brokers,
repeated co-location of subjects who never call each other, and handsets active
while their registered user is in judicial custody. Each finding states the rule
that fired and the numbers behind it.

**7. Answers questions in plain English** and always restates its own
interpretation, so a misread question is visible immediately.

**7a. Opens on a dashboard, and gets out of the way.** A case overview with the
headline figures, what fired, where the evidence came from, how well corroborated
it is, and how the network moved week by week. <kbd>⌘K</kbd> searches subjects
(Devanagari spellings included), findings, views and questions from anywhere;
<kbd>1</kbd>–<kbd>6</kbd> switch views; every chart has a table behind it; light
and dark both ship.

**8. Replays the network over time.** Every edge is timestamped; the timeline
slider shows the network as it stood on any date, or animates how it formed.

**9. Exports court-ready PDFs.** Subject profiles, connection analyses and case
summaries render to paginated PDFs with a classification banner, the evidence
table, the generating officer, and a SHA-256 digest printed on the page so a
copy can be matched against the audit entry recorded when it was made.

**10. Logs everything, tamper-evidently.** Role-based access control plus a
hash-chained audit log written before any answer is returned. Altering any entry
breaks every hash after it, and `/api/audit/verify` names the broken entry.
Set `CNAS_AUDIT_KEY` and payloads are encrypted at rest with AES-256-GCM — the
chain covers the ciphertext, so integrity is verifiable by someone who cannot
read the contents.

## Design decisions worth defending to judges

**Precision over recall on identity.** Attaching a phone number to the wrong
person fuses two unrelated people into one node, and every downstream inference
inherits the error. Phone ownership is therefore only asserted from an explicit
textual cue ("namely Nadeem Ansari (mob. 9000000006)"). Ambiguous mentions are
deliberately left unattributed. An earlier proximity-based version of this code
silently merged two unrelated suspects; the fix is documented in
`pipeline/ingest.py`.

**"No record" never means "cleared."** The clean-skin detector only fires for
people actually present in the criminal-history database with zero prior cases.
Absence of a record means *not found*, and the UI and reports say so.

**Nothing is asserted that cannot be shown.** Every edge, score and finding
carries its sources and the rule that produced it. The "Evidence" panel quotes
the underlying FIR or surveillance text verbatim.

**Colours were validated, not chosen.** The categorical slots, the ordinal ramp
and the status roles were each run through a colour-vision-deficiency validator
against the exact light and dark surfaces the app renders on. Node type also
carries shape, because five entity types exceed the number of hues that stay
separable under CVD when any pair can appear side by side in a node-link
diagram — so identity never rests on colour alone. Every chart has a table view,
so no value is reachable only by hovering.

**No CDN, no build step, no database.** Venue wifi fails. The console is plain
ES2020 with a hand-written force-directed layout on canvas, so the demo runs on
a laptop with no network. All state comes from the REST API, so porting the view
to React + Cytoscape touches nothing else — and `graph/store.py` is the single
module that knows the storage engine, so Neo4j is a swap rather than a rewrite.

**Every capability degrades to a stated fallback.** No OCR binary? Scanned pages
are skipped and the System view says so. No SciPy? A pure-Python PageRank runs.
No LLM? Summaries are template-generated and cannot invent a fact. No reportlab?
The PDF endpoint returns a clear 503 rather than a stack trace. Nothing silently
produces a worse answer while claiming to be fine.

**The LLM is guard-railed, not trusted.** When an LLM backend is configured it
sees only structured facts already derived from source records, never raw case
text. Its output is then checked: every name it mentions must appear in those
facts, or the draft is discarded and the template version is used. Machine-drafted
text is labelled as such in the interface.

**The same question must give the same answer twice.** Python randomises string
hashing per process, and Louvain is stochastic, so early builds produced
modularity 0.505 on one run and 0.507 on the next — and occasionally a finding
appeared or vanished. Organisation node ids are now derived with SHA-1 rather
than `hash()`, the graph is relabelled to integers before community detection,
gazetteer ordering is fully specified, and Louvain runs across sixteen seeds with
the best-scoring partition kept. `scripts/verify.py` asserts byte-identical
output across separate processes. An investigator who reruns an analysis and
gets different groups will, correctly, stop trusting the tool.

**A detector that stops firing when the data grows is worse than none.** The
insulated-actor rule originally used a hand-tuned reach-to-degree ratio, and
adding a few documents silently switched it off. It now reads the sign of the
Shapley attribution instead — a subject whose ranking is driven by betweenness
while contact count contributes least — so there is no constant to recalibrate.

`demo-supervisor`, `demo-admin` or `demo-viewer`.

## Known limitations

- The rule-based extractor is tuned to the synthetic corpus. Real FIR text needs
  a trained multilingual NER model; the interface for that is already in place,
  and Devanagari handling currently rests on a gazetteer plus a phonetic
  skeleton rather than a learned model.
- Devanagari OCR needs the `hin` Tesseract language pack. Without it, scanned
  Hindi pages are skipped rather than mis-read — a deliberate choice, since a
  garbled name is worse than a missing one.
- The Neo4j path is exercised through the Cypher export, not against a live
  cluster; `Neo4jStore` is written but untested against a real server.
- The natural-language parser is intent-based, not a general text-to-query
  engine. It is honest about what it understood, which matters more than range.
- Layout, thresholds and weights are tuned for a network of this size and would
  need recalibration on agency-scale data.
- This is a prototype built for a hackathon. It is an investigative aid, not
  evidence, and no operational decision should rest on it unverified.
